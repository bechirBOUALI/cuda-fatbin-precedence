How one kernel gets chosen

A fat binary carrying six compiled forms of the same kernel arrives at the driver. Five of them are dead code before the GPU sees anything. Here is which field kills each one.

1 A fat binary reaches the driver Six entries, all compiled from the same kernel source.

This exact container was built and run. With bit 24 set on entry 3 the GPU returns marker 0xBBBB, and with that single bit cleared it returns 0xAAAA, because entry 3 then wins on file order instead. Nothing else in the file changes. The rule is the driver's own, measured on 29 conflicting cases and confirmed in the driver binary; every field it reads sits in the entry header, and the compiled code is never consulted until one entry has already won.
